## 4. Performance — P2 FINDING (threshold missed, scope not expanded)

Case: `scripts/build_perf_case.py` → `/tmp/p028-perf-case`
(copilot-cli; 500 modular candidates + 10 `AGENTS.md` = **510 sources**;
**100 edges**, all allowed, `WITHIN_CUSTOM_DIR`; **10 git roots**,
proven by 10 distinct `git.repo` values in the receipt; CWD is a
non-git directory, `repo_root: null`, synthetic empty home).
Measured with `scripts/measure_perf.py --runs 21`
(`review/tasks/P028-T014/perf-results.json`):

| Metric | Value |
|---|---|
| n | 21 |
| p50 | **5.187 s** |
| p95 | **7.828 s** |
| max | 7.837 s |
| min | 4.739 s |
| mean | 5.933 s |
| Threshold (plan §19.3 / book §17) | p95 ≤ 500 ms |
| Verdict | **P2 FINDING — threshold missed by ~15.7×** |
| Runs' exit / verdict / hash | all exit 20, `BLOCK`, one hash `5cd2933b…` |

Why it is slow (measured, not guessed): every source's git state is
probed with up to 4 `git` subprocess spawns (`rev-parse` +
`ls-files` + `status` + `log`) because the CWD has no repo root of
its own, so `get_git_state` discovers each source's repo from scratch
— 510 sources × ~4 spawns ≈ 2,040 git invocations per verify. The
single-run wall time (~5.3 s) is dominated by that; interpreter
startup is ~0.1 s. No optimization was attempted, per the task and
plan §19.3 ("record it, do not expand scope").

Why the verdict is BLOCK (not a defect): with `repo_root: null` the
trust classifier reports every source `OUTSIDE_REPO` (510/510) even
though each file is git-tracked inside its own repo — that is the
frozen single-repo-root trust model (one snapshot repo root; sources
outside it are outside). A 10-genuinely-probed-roots case *requires*
`repo_root: null`, so BLOCK is the product's honest answer for this
case, not a case-construction error. (First attempt built the case
inside the workdir: the outer repo became the single root, all
sources `GIT_UNTRACKED`, 1 root — wrong case, discarded; the
generator now defaults to `/tmp` precisely to avoid that.)

Normal CLI path unaffected: demo `verify` (codex, 4 sources), 21
runs — **p50 148.8 ms, p95 282.1 ms, max 294.9 ms, mean 163.9 ms**,
exit 0, one hash `efd5e4a0…`. The p95 breach is specific to the
500-source / 10-root synthetic case, not to ordinary use.

Carried as **P2-01 (T014, new)**: large-case `verify` p95 7.828 s vs
500 ms threshold; cause = per-source git subprocesses; normal CLI
unaffected. No fix in this task.
