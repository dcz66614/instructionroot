## 3. Book-vs-plan conflicts found while writing the README

The book (`00_contract/PROJECT_BOOK.md`) wins where it is more specific, per
the task brief. Conflicts found:

1. **Claude `@` import max depth — the material one.** Plan §3.3 / §10.3 and
   book §15.2 (S13/S14) agree with each other ("≤ 5"; depth 5 PASS, depth 6
   BLOCK) — but **both disagree with the implementation**, which follows
   SPEC-01 (coordinator ruling in `review/S0_GATE.md`, grounded in the
   official doc): max depth **4 hops**; depth 4 PASS, depth 5 BLOCK
   (`DEPTH_EXCEEDED`). The book/plan text is a spec defect; the README
   discloses it as limitation 2 and `profiles/claude.py` carries the same
   note. The README follows the implementation (depth 4), not the spec text.
2. **Config shape.** Book §14.2 shows `"policy": { …inline object… }` in the
   config example; the shipped `scripts/run-verify.sh` treats `policy` as a
   **path** to a policy JSON file (matching the CLI's `--policy` flag) — noted
   in that script's header. The README describes the shipped behaviour
   (config keys `harness, cwd, home, policy, allow_warn`, policy = path) and
   does not reproduce the book's inline-object example.
3. **Example CLI output.** Book §7.1 / §19.2 show an illustrative terminal
   format (`FAIL`, `receipt: .instructionroot/receipt.json`, `source_count =
   5`…). The real CLI prints `VERDICT: PASS (exit 0)`, `sources=4 blocked=0
   warnings=0`, `receipt_hash: …`. The README pastes only real observed
   output, never the book's illustration.
4. **Directory layout.** Book §21 lists `src/instructionroot/`, `oracle/`,
   `tests/`; the actual repo uses the factory workspace layout `02_src/`,
   `03_oracle/`, `05_tests/` (also plan §1.1). The README's layout section
   shows the real tree.
5. **Demo mode.** Book §10.3 describes a built-in synthetic malicious-looking
   demo workspace (Downloads `AGENTS.md`, `CLAUDE.md` importing Downloads).
   What actually ships is `fixtures/demo` (PASS) + `fixtures/demo-block`
   (BLOCK via symlink escape) + the `web/` receipt viewers. The README
   documents the shipped fixtures, not the book's sketch.

No other book/plan conflict affecting the README was found. The plan §18
checklist is fully covered: first-screen 8 questions, MIT (linked), official
profile URLs, known limitations, no-LLM statement, zero-network statement,
S0 evidence.
