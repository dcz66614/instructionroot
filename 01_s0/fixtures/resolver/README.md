# Resolver Golden Fixtures (T003)

Synthetic workspaces for the harness resolution engine, generated by
`build_resolver_fixtures.py` (re-run it to rebuild; do not hand-edit
the case trees). All content is synthetic placeholder text; zero
real users, zero real repos.

## Layout

```text
01_s0/fixtures/resolver/
├── build_resolver_fixtures.py   # generator (deterministic, idempotent)
├── manifest.json                # case list
└── <case-id>/
    ├── case.json                # input (see below)
    ├── <case-id>.expected.json  # expected discovery output
    ├── home/                    # synthetic HOME
    ├── repo/                    # synthetic repo (no .git: git state is T004)
    └── extra/                   # synthetic custom-instructions dir, if any
```

## `case.json` — T003 extensions to the frozen format

The frozen format is `01_s0/fixtures/README.md` §2. T003 adds three
optional fields (all default to empty):

| field | meaning |
|---|---|
| `working_files` | files (relative to the case dir) the harness is working with — the on-demand triggers (Claude nested / path-scoped rules, Copilot `applyTo` and nested-in-path locations) |
| `env` | environment variables for the run; `{case}` is replaced with the case directory's absolute path (e.g. `COPILOT_CUSTOM_INSTRUCTIONS_DIRS: "{case}/extra"`) |
| `policy` | `"default"` or an inline policy object merged over the frozen defaults |

`repo_root` may be `null` (non-git workspace, S25). The golden runner
bounds Claude's upward ancestor walk at the case directory
(`ancestor_stop`), so discovery cannot escape the fixture.

## `<case-id>.expected.json` — resolver-stage scope

Resolver-stage expected files assert **discovery fields only**:

```json
{
  "expected_sources": [
    {"discovery_rule": "codex.repo-chain", "scope": "project",
     "phase": "startup", "relative_path": "repo/AGENTS.md",
     "precedence_kind": "ORDERED",
     "also_discovered_by": ["copilot-cli.custom-dirs"]}
  ],
  "expected_not_applicable": [
    {"relative_path": "repo/.github/instructions/docs.instructions.md",
     "reason": "APPLYTO_NO_MATCH"}
  ],
  "expected_import_candidates": [
    {"from_relative_path": "repo/CLAUDE.md", "syntax": "@shared/a.md",
     "depth": 1, "relative_target": "repo/shared/a.md",
     "allowed": true, "reason": "OK"}
  ],
  "expected_source_count": 3
}
```

`trust` and `expected_verdict` are deliberately absent: trust is
T004's job and the verdict is T008's; T007's full expected files
assert them. `relative_path` / `relative_target` are relative to
the case directory; the runner compares canonical absolute paths.

## Comparison rules (`scripts/run_golden.py --stage resolver`)

- **set**: the multiset of `(discovery_rule, canonical_path)` must
  match exactly, for every harness.
- **order**: for `codex` / `claude-code` the ordered list must match
  exactly. For `copilot-cli` (`COMBINE_UNORDERED`) order is *not*
  asserted — the order score for a Copilot case is its set result,
  and the emitted order is enumeration order only.
- **not-applicable**: when `expected_not_applicable` is non-empty,
  the `(relative_path, reason)` pairs must match exactly.
- **import candidates**: when `expected_import_candidates` is
  non-empty, the `(from, syntax, depth, target, allowed, reason)`
  tuples must match exactly (Claude only, SPEC-01 depth max 4).
