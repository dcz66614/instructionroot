# T002 filesystem fixtures — synthetic only

Layout (generated by `build_fs_fixtures.py`, re-runnable and idempotent;
committed trees are exactly what the script produces):

```text
01_s0/fixtures/fs/
├── README.md                  # this file
├── build_fs_fixtures.py       # generator (run: .venv/bin/python <this file>)
├── manifest.json              # generated case list
└── cases/<case-id>/
    ├── case.json              # {case_id, title, os, synthetic}
    └── <synthetic tree>       # home/ repo/ outside/ …
```

Cases: `basic`, `dotdot`, `symlink-inside`, `symlink-escape`,
`symlink-loop`, `symlink-broken`, `unicode`, `missing`, `separators`,
`deep-chain`, `dir-symlink`, `windows`.

Rules (PROJECT_BOOK.md §15.1, fixtures README §1):

- All content is synthetic placeholder text. No real user home, no
  real repo, no real instruction-file content, no malicious payload.
- `windows/` holds **pure-string** cases only
  (`windows-paths.json`): drive-letter / UNC spellings that can be
  normalised without a Windows filesystem. Real junction and
  drive-letter *resolution* is NOT_RUN on Linux and belongs to T011
  on a Windows runner — never faked as passing here.
- Unit tests in `05_tests/unit/test_paths.py` build their own
  hermetic trees under `tmp_path` for assertions; the committed trees
  exist so T003/T007 can reuse the same shapes, and one test verifies
  a snapshot of `cases/basic` is deterministic.
